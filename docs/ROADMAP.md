# Home Glance Roadmap

Home Glance is in public testing. This roadmap shows the planned direction of development without promising fixed release dates. Priorities can still change when testing exposes a more important compatibility or reliability issue.

The latest published APK is **v0.2.3**, a public test prerelease. Development builds and experiments are not part of the public download until they are explicitly released.

## Development order

The roadmap is intentionally ordered by dependency. The first goal is to build the tools that make every later integration easier to diagnose, test and maintain.

### Priority 01 — Diagnostics and bug-reporting system

This is the first item to implement.

Planned scope:

- Internal Home Glance diagnostic log
- Optional temporary diagnostic mode, for example a 10-minute capture session
- ZIP diagnostic report generated by the app
- Device, Android, ROM/build, app version and widget state information
- Permission and battery-optimization status
- Weather provider, calendar, Google Tasks, media-session and Bluetooth diagnostics
- Crash and abnormal-exit information where Android exposes it
- Privacy-safe defaults: no calendar titles, task names, exact location, account data or raw device identifiers unless explicitly needed
- Share the finished report through the Android system share sheet
- Specialized diagnostic flows for weather, media and headphones testing

The long-term goal is to replace as much manual ADB/logcat troubleshooting as possible with a user-friendly in-app workflow.

### Priority 02 — Provider and adapter architecture

Create a formal extension layer before adding many more integrations.

Planned architecture:

- `WeatherProvider`
- `HeadphonesAdapter`
- `MediaProvider`
- Other provider interfaces where future integrations need them

The main widget should not need to know Sony-, Samsung-, Xiaomi- or API-specific implementation details. New integrations should be added as isolated modules instead of scattered special cases.

### Priority 03 — Compatibility Center

Add a dedicated status page showing what works on the current device.

Planned checks:

- Weather
- Calendar
- Next alarm
- Google Tasks
- MediaSession
- Bluetooth
- Headphones battery support
- Left / right / case battery support
- ANC / Transparency capability
- Required permissions
- Battery optimization or background restrictions
- Known OEM-specific limitations

Each item should clearly show whether support is available, limited or unavailable on the current device.

### Priority 04 — Automatic hardware compatibility reports

Build a guided test flow for new hardware, especially headphones.

A tester should be able to perform actions such as:

- Connect the device
- Read battery state
- Switch ANC / Transparency / Off
- Disconnect
- Reconnect

Home Glance should record what succeeded, what failed and which protocol/adapter response was received. This will make remote testing possible without requiring every tester to understand ADB.

### Priority 05 — Stable and Beta channels

Add a clear release-channel choice.

Planned behavior:

- Stable channel for confirmed integrations
- Beta channel for experimental providers, adapters and compatibility work
- New hardware integrations can be tested before reaching all users
- Stable users should not be exposed to unverified device-specific code

### Priority 06 — Automatic capability detection

Home Glance should detect relevant capabilities and suggest the best configuration while keeping user choice.

Examples:

- Xiaomi device → suggest compatible Xiaomi weather source when available
- Galaxy Buds → suggest Samsung adapter
- No Google Play Services → hide or clearly mark unavailable Google-dependent features
- Unsupported headphones → fall back to generic Bluetooth information

The app should guide the user without forcing a specific setup.

### Priority 07 — Weather provider expansion

Expand weather sources while keeping provider choice fully under user control.

Planned work:

- Multiple weather providers
- Provider selector in settings
- Provider-specific configuration where required
- Clear provider/network error states
- Factory-installed OEM weather sources where technically possible
- Xiaomi Weather, Samsung Weather, OnePlus/Oppo Weather and other manufacturer apps investigated as direct data sources
- Prefer the same underlying weather data as the app opened from the widget when possible

A major goal is to avoid situations where Home Glance shows, for example, 17°C while the weather app opened by the user shows 16°C.

### Priority 08 — Headphones compatibility expansion

Expand the headphones page to many manufacturers and models.

Target families include, where protocol information is available:

- Sony
- Samsung Galaxy Buds
- Nothing / CMF
- Xiaomi / Redmi
- OnePlus / Oppo / Realme
- JBL
- Additional manufacturers as they are researched

Possible features per adapter:

- Device name/model
- Left battery
- Right battery
- Case battery
- ANC
- Transparency / Ambient mode
- Off
- Manufacturer-specific controls where practical

Implementation can begin from public protocol documentation and reverse-engineered open-source projects, but a model should only be treated as confirmed after real-device testing.

### Priority 09 — Font system redesign

Replace the current small font list with a broader, consistent system.

Planned scope:

- 10 selectable font styles
- Keep System
- Keep the current Sans Serif / Google-like style
- Add Google Sans where redistribution is legally permitted, otherwise use a suitable legal alternative
- Add seven other popular, high-quality fonts
- Include the current Music/Headphones typeface if it is distinct and fits the final set
- Apply the selected font consistently to all three widget pages:
  - Home
  - Music
  - Headphones

### Priority 10 — Settings backup and import

Allow users to export and restore Home Glance configuration.

Planned scope:

- Export settings to a JSON file
- Import settings after reinstalling, changing ROM or changing phone
- Restore appearance, weather, calendar, media and other configuration where safe
- Version the backup format so it can evolve over time

### Priority 11 — Widget profiles and presets

Allow complete configurations to be saved and switched as presets.

Example profiles:

- Minimal
- Pixel
- Large text
- Calendar-focused
- Music-focused
- User-created profiles

A profile should be able to store multiple settings at once instead of requiring manual reconfiguration.

### Priority 12 — Settings search

Add a search field once the settings surface becomes larger.

Examples:

- `ANC`
- `font`
- `weather`
- `calendar`

Search should navigate directly to the relevant setting or section.

### Priority 13 — Advanced media mode

Extend the media page beyond standard music playback.

Planned ideas:

- Podcast support
- Audiobook support
- ±15 / ±30 second seek actions where exposed by MediaSession
- Chapter information
- Time remaining
- Better handling of media apps with non-standard controls
- Keep the current generic MediaSession approach rather than hard-coding support for individual players whenever possible

### Priority 14 — More task and calendar sources

After Google Tasks, investigate additional providers.

Possible future sources:

- Microsoft To Do
- Outlook
- CalDAV
- Nextcloud
- Other standards-based task/calendar services

These should use the provider architecture rather than being directly embedded into the main widget code.

### Priority 15 — Automatic widget-page switching

Add an optional smart page mode.

Possible behavior:

- Home remains the default page
- Start media playback → optionally switch to Music
- Connect supported headphones → optionally switch to Headphones
- Playback ends / headphones disconnect → return to Home

This must remain optional so users who prefer manual navigation keep full control.

## Development phases

### Foundation

Priorities **01–06** are the technical foundation. They should be completed before aggressively expanding device- and service-specific integrations.

### Integrations

Priorities **07–09** are the main compatibility and customization expansion.

### Product maturity

Priorities **10–15** focus on portability, usability, discoverability and advanced behavior.

## Ongoing work

Alongside the roadmap above:

- Fix compatibility issues across Android devices and launchers
- Improve weather, calendar, alarm, Tasks and media reliability
- Expand localization
- Improve accessibility
- Keep installation, update and feedback flows stable
- Continue testing on real devices rather than relying only on emulators

## Project philosophy

**Slow down. It’s enough.**

**Build the tools first, then add the features.**

Home Glance is inspired by the simplicity of Another Widget and aims to become its modern spiritual successor, but the goal is not a visual clone.

The project should grow carefully: first create the diagnostics, architecture and test tools needed to understand failures, then scale the number of providers, devices and features without turning the codebase — or the home screen — into noise.
